## 2. Attendance, evidence and stop rules

**REMOTE:** review from GitHub/evidence without NAS login. **HOST:** authorized human using NAS console/SSH, watching only the new project. **ONSITE:** operator *physically present* with NAS/local or out-of-band recovery and relevant authorized desktop/mobile client; mandatory for state-changing provisioning, live browser/client checks, tunnel-loss injection, writer quiescence, restore/rollback and deliberate failure injection. HOST tasks should be treated as ONSITE if remote recovery is unavailable.

For every checkbox record: case ID, UTC time, operator, exact git SHA, Compose project, profiles, image digest/architecture, effective numeric UID:GID, fixture ID, expected vs observed, PASS/FAIL/BLOCKED, private artifact/checksum, and rollback result. Use access-restricted reports. Redact credentials, cookies, host paths, real library/media filenames, tokens, NGINX config bodies, raw Docker environments, WireGuard keys, provider session details and user data before publishing issues.

**STOP / NO-GO:** unknown or overlapping writable mount; reused project/container or port; unverified backup; unhealthy or leaking managed VPN; unauthenticated module access; loss/duplicate of media bytes; auth lockout; database/plugin incompatibility; a secret appearing in logs; or inability to recover. Do not run docker compose down -v, prune, mass cleanup, recursive chmod/chown, or disable the VPN firewall as a workaround.

## 4. Stage B — P0 secrets and NGINX ingress

- [ ] **B01 [HOST] Numeric UID/GID audit.** Record configured FOXDEN, MUSIC, MEDIA, QBIT, JELLYFIN service PUID/PGID and Gluetun root key owner. The historical operator 1003:10 and Music 1000005:1000004 are not general assumptions. **PASS:** exact intended reads and writes, no world-readable secrets. **FAIL:** access denial or excess grant. **Evidence:** stat -c with %u:%g and numeric ACL summary.
- [ ] **B02 [ONSITE] Explicit opt-in provisioning.** Only on isolated test paths and after verifying no symlink/path overlap, run init --create-paths --apply-permissions with authorized host root, then --check-service-owners. The operation creates missing secrets/optional placeholders and can change metadata: it is **not a read-only command**. It must not rotate existing secrets or recursively modify populated/shared paths. **PASS:** named secret leaves owner-only mode 0600 (public identity JSON intentionally 0644), copied app state preserved. **FAIL:** secret byte change, shared data ownership change, ACL failure. **Evidence:** private before/after checksums and stat, never values.
- [ ] **B03 [HOST] Per-service bind access.** Verify Portal signing/ingress/bootstrap secret reads; Music music-csrf and optional jellyfin-api-key; Media app-token/qbit-password; Gluetun root-only WireGuard key; app config/staging/shared library read/write under actual container identities. **PASS:** read/write where expected with no chmod 644/777 workaround. **FAIL:** unreadable mounted file or excessive access. **Evidence:** owner summary + scoped health/error statuses.
- [ ] **B04 [HOST] Validate/dry-run immutability.** Record nginx.conf mode/uid/gid/inode/hash in isolated runtime; run foxden validate, deploy without --execute, stop without --execute. **PASS:** no new config or inode mutation and no stopped containers. **FAIL:** configuration write or service change. **Evidence:** before/after metadata.
- [ ] **B05 [ONSITE] Authorized NGINX render.** Explicit foxden config render (privileged if needed) should create a 0600 regular file owned by ingress numeric UID:GID, refusing symlinks/hardlinks/unsafe target; repeat unchanged and verify inode stable. In a separate sacrificial configuration copy, inject failed chown or unsafe target and ensure previous content survives. A changed *test-only* nonsecret routing value requires **targeted ingress recreate** to refresh Docker file-bind inode. **PASS:** nginx -t passes, only ingress refreshed, routes healthy; failure retains old config. **FAIL:** stale inode, bad owner, exposed secret or stateful writer recreated. **Evidence:** stat/hash and sanitized nginx -t/ps, never config body.
- [ ] **B06 [HOST; ONSITE for interactive] Ingress authorization.** Anonymous /, /music/, /media/ and /server-browser/ must redirect/deny; general user cannot reach admin acquisition/browser/API; admin can access selected enabled module. Test spoofed identity headers, logout, session expiry, SSL/cookie and WebSocket upgrade behavior. **PASS:** fail-closed routes and no directly published Music/Media/Firefox/Jellyfin service ports. **FAIL:** direct bypass, 5xx after regen, unauthorized admin route. **Evidence:** redacted HTTP status and routing matrix.

Review-only controller commands (the first two validate/dry-run; the third *writes* private NGINX and runs Compose config, so require authorized test root):

    sudo python scripts/foxden.py validate full-managed --env "$REHEARSAL_ENV" --browser --jellyfin --check-service-owners

    docker compose --env-file "$REHEARSAL_ENV" -f deploy/compose.yaml --profile music --profile media --profile managed --profile browser --profile jellyfin exec -T ingress nginx -t

Private file metadata example: stat -c '%n %u:%g %a %i' /APPROVED/ISOLATED/runtime/nginx.conf. Never display its secret-bearing body.
